This diagram presents a **PostgreSQL Architecture Diagram**, showing the flow from client requests to disk-level operations. Here’s a **short description** of each component:

---

### 🔸 **Client**

* External user or application sending SQL queries to the PostgreSQL server.

---

### 🔸 **Postmaster**

* The **main daemon** of PostgreSQL.
* Accepts incoming connections.
* Spawns new backend processes (`postgres`) for each client.

---

### 🔸 **Postgres Processes**

* Separate **backend processes** created by Postmaster.
* Each handles one client session.
* Responsible for parsing, planning, executing SQL, and returning results.

---

### 🔸 **Shared Buffer**

* Central **shared memory** used for caching table data and indexes.
* Reduces direct disk I/O by storing frequently accessed data.

---

### 🔸 **WAL Buffer**

* Temporarily stores **Write-Ahead Log** entries before flushing to disk.
* Ensures data durability.

---

### 🔸 **Work Mem**

* Per-operation memory used for sorting, hashing, etc.
* Not shared; scoped to individual SQL operations.

---

### 🔸 **Maintenance Work Mem**

* Used by background maintenance tasks like **VACUUM**, **CREATE INDEX**, etc.

---

### 🔸 **CLOG Buffer**

* **Commit Log buffer**: Tracks transaction commit statuses for recovery and concurrency control.

---

### 🔸 **Temp**

* Stores temporary data (e.g., for complex queries or temporary tables).

---

### 🔸 **Background Processes**

#### 🟠 **Stats Collector**

* Gathers performance metrics and activity statistics for monitoring.

#### 🟠 **Checkpointer**

* Periodically writes dirty pages (modified data) from shared buffer to disk.

#### 🔵 **Auto Vacuum Launcher**

* Launches autovacuum workers to remove dead tuples, preventing table bloat.

#### 🔴 **WAL Writer**

* Flushes WAL buffers to disk files in the `pg_wal` directory.

#### 🟡 **Logging Collector**

* Collects logs generated by server processes and writes to log files.

#### 🔴 **BG Writer (Background Writer)**

* Writes modified (dirty) pages from shared buffers to disk in the background.

#### 🔵 **Archiver**

* Archives WAL files for **Point-In-Time Recovery (PITR)**.

---

### 🔸 **Disk Components**

* **Data**: Stores actual table and index data files.
* **Log**: Stores general server logs.
* **WAL**: Write-Ahead Logs for crash recovery.
* **Archive Log**: Archived WAL files used for backup and PITR.
